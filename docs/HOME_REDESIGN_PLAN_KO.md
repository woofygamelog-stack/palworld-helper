# Palworld Helper 홈 화면 개편 상세 작업계획

> 기준일: 2026-08-01<br>
> 대상: `/{locale}` 홈 화면 17개 로케일<br>
> 작업 분류: 제품/정보구조, UI·접근성, 현지화, SEO, 성능, 측정<br>
> 결정: **진행(Go)** — 신규 기능이나 라우트를 늘리지 않고, 현재 구현된 콘텐츠의 발견성과 연결성을 개선한다.
> 구현 상태: **완료** — 2026-08-01 공통 매니페스트·17개 언어·런타임/정적 공용 렌더러·산출물 검증·브라우저 QA 반영.

## 1. 개편 목표

현재 홈은 큰 마케팅 히어로와 `팰 도감`, `교배 계산기` 두 개의 실행 버튼만 제공한다. 그러나 실제 사이트는 지도, 팰·스킬, 세 종류의 계산기, 여러 데이터베이스, 서버 설정 도구까지 제공한다. 홈이 사이트의 실제 범위를 설명하거나 사용자의 다음 행동을 안내하지 못하는 것이 가장 큰 문제다.

이번 개편의 목표는 다음과 같다.

1. 사용자가 사이트 구조를 학습하지 않아도 “지금 하려는 일”에서 바로 시작하게 한다.
2. 지도·계산기·데이터베이스·서버 도구를 한 화면에서 균형 있게 발견하게 한다.
3. 전체 검색을 홈의 가장 중요한 공통 진입점으로 만든다.
4. 데이터의 범위와 정확성 원칙은 설명하되, 사이트 전체가 모두 검증 완료된 것처럼 과장하지 않는다.
5. 정적 초기 HTML과 자바스크립트 실행 후 홈 콘텐츠를 동일하게 유지한다.
6. 17개 공식 지원 언어, 라이트·다크·시스템 테마, 모바일·키보드·스크린리더 사용성을 같은 변경에서 완성한다.
7. 새로운 게임 사실, 미구현 도구, 미완성 가이드, 공개 금지 버전 정보를 홈에 추가하지 않는다.

## 2. 조사 범위와 근거

### 2.1 저장소 기준선

다음 자료를 기준선으로 사용했다.

- 제품 사양: `PALWORLD_HELPER_PLAN_KO.md`
- 현재 구현 범위: `IMPLEMENTATION_STATUS_KO.md`
- 구현·색인 라우트: `src/route-manifest.ts`
- 런타임 홈: `src/main.ts`의 `home()`
- 정적 홈: `scripts/seo-static.mjs`의 홈 모델
- 디자인 토큰과 히어로: `src/styles.css`, `src/features.css`
- 홈 SEO 산출물: `dist/ko-KR.html`, `dist/en-US.html`
- 하이브리드 렌더링 보고서: `dist/prerender-report.json`

현재 구현 기준 주요 콘텐츠는 다음과 같다.

| 영역 | 현재 제공 내용 | 홈 노출 판단 |
|---|---|---|
| 지도 | 팔파고스·세계수, 검증된 보스·빠른 이동·서식지·던전/NPC 연계, 로컬 핀 | 빠른 시작 핵심 |
| 팰 | 299종, Paldeck 순서, 능력치·작업 적성·스킬·관계 | 빠른 시작 핵심 |
| 스킬 | 액티브·패시브·파트너 스킬 | 데이터 탐색 |
| 계산기 | 교배, 다중 목표 제작 재료, 거점 핵심 팀 | 빠른 시작 핵심 |
| 아이템/레시피 | 1,891개 합법 아이템, 1,286개 유효 제작식 | 데이터 탐색 및 제작 흐름 |
| 데이터베이스 | 퀘스트 82, 건축물 472, 원정 18, 속성 9, 기술 588, NPC 164, 던전 28, 팰 건강 | 주제별 탐색 |
| 서버 도구 | 공식 문서에 존재하는 설정만 사용한 INI 생성·가져오기·검증 | 빠른 시작 핵심 |
| 언어 | 공식 지원 17개 로케일 | 신뢰·범위 설명 |

교배 결과 44,851행은 무결성 검사를 통과했지만 독립 검증이 남아 있다. 따라서 이 수를 홈의 “검증 완료” 통계로 사용하지 않는다.

### 2.2 현재 홈의 구체적 문제

1. **대표성 부족**<br>
   런타임 홈은 팰 도감과 교배 계산기만 노출한다. 지도, 제작 계산기, 거점 플래너, 스킬, 아이템 외 데이터베이스, 서버 도구는 홈에서 찾기 어렵다.

2. **검색 진입 약함**<br>
   전체 검색은 헤더 버튼과 모바일 하단 메뉴에만 있다. 제품 계획이 요구하는 “홈의 전체 검색”이 실제 주 콘텐츠에 없다.

3. **히어로가 과대하고 정보가 적음**<br>
   데스크톱에서 최소 높이 620px, 최대 7.6rem 제목을 사용하지만 그 아래에 실질 콘텐츠가 거의 없다. 모바일에서도 제목이 3.7rem으로 고정되어 첫 화면에서 실행 가능한 선택지가 늦게 나타난다.

4. **정적/런타임 화면 불일치**<br>
   정적 홈은 팰·교배·아이템·퀘스트·건축물·원정·속성·기술·던전 링크를 제공하지만, 자바스크립트 초기화 후 이 목록이 사라지고 두 버튼만 남는다. 이는 사용자 경험, 내부 링크, 초기 HTML과 런타임 콘텐츠 일관성에 모두 불리하다.

5. **메시지 범위가 좁고 과도하게 단정적임**<br>
   현재 설명은 팰 이름, 능력치, 교배만 언급한다. “검증된 데이터셋”이라는 전역 표현은 독립 검증이 남은 교배 데이터까지 모두 검증 완료로 읽힐 수 있다.

6. **광고가 첫 가치 영역 바로 다음에 위치함**<br>
   광고 슬롯이 설정된 경우 히어로 다음 섹션이 광고가 된다. 사용자가 사이트의 실제 기능을 이해하기 전에 광고를 만날 수 있다.

7. **오래된 제품 계획과 현재 계약의 충돌**<br>
   초기 계획은 홈에 게임 버전과 갱신일을 공개하도록 했지만, 최신 프로젝트 계약은 공개 UI·SEO·구조화 데이터에 빌드/데이터 버전/업데이트 버전을 노출하지 않도록 요구한다.

### 2.3 경쟁 홈 화면의 제한적 조사

이 작업은 기존 사이트의 홈 UI 개편이며 신규 사이트나 신규 대형 라우트군 선정이 아니다. 따라서 Google Trends와 전체 시장 점수표는 반복하지 않고, 홈 발견성에 직접 영향을 주는 경쟁 패턴만 2026-08-01에 확인했다.

## 3. 제품 결정과 범위

### 3.1 이번 개편에 포함

- 홈 히어로 카피와 크기 재설계
- 홈 본문에 전체 검색 실행 영역 추가
- 과업 중심 빠른 시작 6개 카드
- 구현된 데이터베이스를 네 개 주제 그룹으로 탐색하는 영역
- 데이터 정확성 원칙과 17개 언어 지원을 설명하는 신뢰 영역
- 광고 위치를 핵심 콘텐츠 이후로 이동
- 정적/런타임 홈을 하나의 콘텐츠 모델로 통합
- 17개 로케일 카피와 번역 provenance
- 홈 전용 SEO 제목·설명 개선
- 접근성·반응형·성능·분석 회귀 테스트

### 3.2 이번 개편에서 제외

- 신규 라우트나 신규 게임 데이터 추가
- 포획률·IV·생산·응축 계산기
- 팀 빌더, 팰 비교, 내 목록
- 초보·복귀·엔드게임 가이드 카드
- 최신 패치/최근 변경 데이터 섹션
- 로그인, 서버 저장, 개인화 추천
- 데이터 획득 방식 변경 또는 데이터 갱신
- 새 캐릭터 일러스트, 게임 UI 복제, 권리 검토가 끝나지 않은 신규 자산
- 프로덕션 배포

가이드·최근 변경·내 목록은 제품 계획에는 있지만 현재 구현 허용 목록과 사이트맵에 없으므로 홈에도 표시하지 않는다. 나중에 각 라우트와 데이터 게이트가 통과한 뒤 별도 확장한다.

### 3.3 사양 충돌 해결

| 충돌 항목 | 결정 |
|---|---|
| 초기 계획: 게임 버전·갱신일 공개 | 최신 프로젝트 계약을 따라 공개하지 않는다. 빌드와 추출일은 내부 데이터·검증·diff에만 유지한다. |
| 초기 계획: 초보·복귀·엔드게임 추천 흐름 | 관련 가이드가 구현·색인 게이트를 통과하기 전에는 제외한다. 기존 기능으로 해결 가능한 과업 카드만 제공한다. |
| 초기 계획: 신규/변경 데이터 요약 | 검증된 `PatchChange` 공개 모델이 없으므로 제외한다. 수동 최신성 문구를 작성하지 않는다. |
| 현재 홈: 전체가 검증된 것처럼 표현 | “확인된 값만 공개하고 미확인 값은 추정하지 않는다”는 원칙 중심 문구로 좁힌다. 데이터별 검증 상태는 각 기능에서 유지한다. |

## 4. 대상 사용자와 홈에서 해결할 일

홈은 사용자 유형을 직접 선택하게 하지 않고, 모든 유형이 공통으로 반복하는 과업을 제시한다.

| 사용자 과업 | 직접 목적지 | 홈에서 전달할 가치 |
|---|---|---|
| 팰·보스·빠른 이동·던전·NPC 위치 찾기 | `/{locale}/map` | 검증된 지도 레이어와 관련 상세 연결 |
| 팰 능력치·작업 적성·스킬 확인 | `/{locale}/pals` | Paldeck 순서와 공식 현지화 이름으로 탐색 |
| 부모 또는 목표 팰의 교배 조합 확인 | `/{locale}/calculators/breeding` | 정방향·역방향 검색 |
| 여러 제작 목표의 재료 합계 계산 | `/{locale}/calculators/crafting` | 합류 수요 선합산, 보유량 1회 차감, 다중 제작식 선택 |
| 목적에 맞는 거점 핵심 팀 구성 | `/{locale}/calculators/base` | 11개 목적 프리셋과 작업 적성 기반 최소 팀 |
| 서버 INI 생성·가져오기·검증 | `/{locale}/server-tools/settings-generator` | 공식 문서 설정만 사용하고 입력은 브라우저에서 처리 |

## 5. 권장 홈 정보구조

### 5.1 화면 순서

```text
[공통 헤더: 브랜드 · 메뉴 · 전체 검색 · 언어 · 테마]

[1. 컴팩트 히어로]
  신뢰 원칙 eyebrow
  H1: 지금 필요한 답에서 시작
  한 문장 설명
  큰 전체 검색 실행 영역
  보조 링크: 팰 / 교배 / 지도
  작은 CSS 기반 탐험 모티프

[2. 무엇을 하려는가?]
  위치 찾기 | 팰 알아보기 | 교배 결과 찾기
  제작 준비 | 거점 팀 구성 | 서버 설정 만들기

[3. 데이터로 더 알아보기]
  팰과 스킬
  아이템·건축물·기술
  퀘스트·NPC·던전·원정
  속성 상성·팰 건강

[4. 데이터 원칙]
  검증된 콘텐츠 우선
  미확인 값은 추정하지 않음
  공식 17개 언어 지원

[5. 광고 영역 — 설정·동의·프로덕션 조건 충족 시]

[공통 푸터]
```

### 5.2 섹션별 상세 명세

#### A. 히어로

권장 한국어 초안:

- eyebrow: `확인된 데이터로 바로 시작`
- H1: `팰월드에서 지금 필요한 답을 찾으세요`
- 설명: `지도에서 위치를 찾고, 팰과 아이템을 살펴보고, 교배·제작·거점·서버 설정을 한곳에서 해결하세요.`
- 검색 라벨: `팰·아이템·스킬·NPC·던전 검색`

구현 규칙:

- 홈의 마케팅 히어로만 설명 문단을 포함할 수 있으며 `h1`은 정확히 하나다.
- 검색 영역은 별도 검색 인덱스를 만들지 않고 기존 전체 검색 다이얼로그를 여는 실행 컨트롤로 구현한다.
- 검색 데이터는 사용자가 검색을 열기 전에는 불러오지 않는다.
- `/` 키 단축키, Escape 닫기, 트리거로 포커스 복귀, 결과 수 안내 등 기존 검색 동작을 그대로 재사용한다.
- 히어로의 기본 높이를 데스크톱 약 460~520px 범위로 축소한다.
- 제목은 `clamp()`로 데스크톱 최대 약 5.2rem, 모바일 최대 약 3.2rem 수준을 목표로 한다.
- 360px 첫 화면에서 H1, 설명, 검색, 최소 두 개의 핵심 실행 선택지가 보이도록 한다.
- 현재 CSS 섬·나침반 모티프는 축소해 유지할 수 있으나, 정보보다 앞서지 않게 한다.

#### B. 빠른 시작 카드

카드는 정확히 6개로 제한한다.

| ID | 제목 | 설명 초안 | 목적지 | 아이콘 |
|---|---|---|---|---|
| `find-location` | 위치 찾기 | 보스, 빠른 이동, 던전과 NPC를 지도에서 찾습니다. | `/map` | `map` |
| `browse-pals` | 팰 알아보기 | Paldeck 순서로 능력치, 작업 적성, 스킬과 관계를 살펴봅니다. | `/pals` | `pals` |
| `calculate-breeding` | 교배 결과 찾기 | 부모에서 결과를 찾거나 목표 팰의 부모 조합을 역검색합니다. | `/calculators/breeding` | `calculator` |
| `plan-crafting` | 제작 준비하기 | 여러 제작 목표와 보유 재료를 합쳐 최종 필요량을 계산합니다. | `/calculators/crafting` | `database` 또는 제작 전용 기존 아이콘 |
| `plan-base` | 거점 팀 구성하기 | 목적과 작업 적성에 맞는 핵심 팰 팀을 구성합니다. | `/calculators/base` | `pals` 또는 작업 전용 기존 아이콘 |
| `configure-server` | 서버 설정 만들기 | 공식 서버 문서 기준으로 INI를 생성하고 가져온 설정을 검사합니다. | `/server-tools/settings-generator` | `server` |

카드 규칙:

- 전체 카드가 하나의 실제 `<a>`여야 하며, 카드 안에 중첩 버튼을 두지 않는다.
- 제목은 `h3`, 섹션 제목은 `h2`로 구성한다.
- 모든 카드는 44px 이상의 클릭 영역, 명확한 hover/focus 상태, 색 외의 아이콘·텍스트 단서를 갖는다.
- 카드 설명은 현재 구현된 기능만 말하며 미구현 기능이나 정확하지 않은 수치를 약속하지 않는다.
- 데스크톱 3열, 태블릿 2열, 모바일 1열을 기본으로 한다.

#### C. 데이터 탐색 그룹

모든 데이터베이스 링크를 한 레벨에 나열하지 않고 네 개의 주제 그룹으로 묶는다.

| 그룹 | 포함 링크 |
|---|---|
| 팰과 스킬 | 팰, 스킬 전체, 액티브, 패시브, 파트너 |
| 아이템·건축·진행 | 아이템, 건축물, 기술, 퀘스트 |
| 탐험과 인물 | 지도, NPC, 던전, 팰 원정 |
| 전투와 관리 | 속성 상성, 팰 건강, 거점 플래너 |

구현 규칙:

- 각 링크는 현재 `routeFamilies`의 indexable 허용 목록에 있어야 한다.
- 데이터 그룹은 카드 하나당 제목, 한 문장 설명, 3~5개의 실제 앵커로 제한한다.
- 상세 엔터티를 홈에 임의 추천하지 않는다. 추천 팰·추천 티어처럼 검증 기준이 필요한 콘텐츠도 추가하지 않는다.
- 수량을 표시한다면 하드코딩하지 않고 빌드 시 생성된 소형 홈 요약 모델에서 가져와야 한다. 첫 구현에서는 수량 없이도 완료 가능하다.
- 내부 ID, 게임 빌드, 데이터 버전은 출력하지 않는다.

#### D. 데이터 원칙

숫자 과시보다 세 가지 제품 원칙을 짧게 제시한다.

1. `검증된 콘텐츠 우선`
2. `미확인 값은 추정하지 않음`
3. `공식 17개 언어 지원`

“모든 데이터 검증 완료”, “항상 최신”, “100% 정확” 같은 문구는 사용하지 않는다. 교배 결과처럼 별도 검증이 남은 영역까지 전역 신뢰 배지가 덮지 않게 한다.

#### E. 광고

- 히어로와 빠른 시작 사이에는 광고를 두지 않는다.
- 빠른 시작과 데이터 탐색을 모두 본 뒤의 독립 섹션에만 배치한다.
- 프로덕션, 동의, 유효한 사이트 전용 슬롯 ID 조건을 모두 만족할 때만 로드한다.
- 슬롯 높이를 예약해 CLS를 방지한다.
- 검색, 카드, 버튼, 모바일 하단 메뉴와 충분한 시각적 간격을 둔다.
- 렌더링, 테마 변경, 검색, 필터, 언어 변경으로 광고를 다시 요청하지 않는다.

## 6. 콘텐츠·라우트 모델 설계

### 6.1 단일 홈 매니페스트

정적 홈과 런타임 홈의 불일치를 없애기 위해 다음 구조를 권장한다.

```text
src/home-manifest.ts
  homeQuickActions
  homeCatalogGroups
  homeTrustItems
  validateHomeManifest()

src/home-i18n.ts
  homeCopy[17 locales]
  homeCopyProvenance

src/home-render.ts
  renderHomeMarkup({ locale, href, adSlot })
```

핵심 원칙:

- `src/main.ts`와 `scripts/seo-static.mjs`가 같은 `renderHomeMarkup()`을 사용한다.
- 렌더러는 DOM 상태나 브라우저 전역에 의존하지 않는 순수 함수로 만든다.
- 링크 생성 함수와 광고 마크업만 호출자가 주입한다.
- 매니페스트의 모든 경로가 `collectionRoutes`에 존재하고 indexable인지 테스트한다.
- 빠른 시작 ID와 그룹 ID는 분석용 안정 식별자로 사용할 수 있지만 URL·화면에 내부 게임 ID를 노출하지 않는다.
- 미구현 라우트를 매니페스트에 추가하면 테스트가 실패해야 한다.

### 6.2 검색 재사용

- 홈 검색 실행 영역에 `data-open-search`를 사용해 기존 `#global-search-dialog`를 연다.
- 검색 다이얼로그를 두 개 만들지 않는다.
- 검색 입력 원문은 Analytics, URL, 로그로 보내지 않는다.
- 홈 진입만으로 `pals.json`, `items.json` 등 대형 데이터 파일을 불러오지 않는다.
- 검색을 처음 열 때 기존 `ensureGlobalSearchData()`를 실행한다.
- 모바일 하단 검색, 헤더 검색, 홈 검색은 모두 같은 상태와 결과 컴포넌트를 사용한다.

### 6.3 정적/런타임 일치

완료 상태에서는 다음이 성립해야 한다.

- `dist/{locale}.html`의 홈 `main`과 런타임 `home()` 출력이 같은 섹션과 링크를 포함한다.
- 초기 HTML의 링크가 자바스크립트 실행 후 사라지지 않는다.
- 제목·설명·canonical·hreflang·구조화 데이터가 앱 초기화 후에도 같은 홈 값을 유지한다.
- 하이드레이션 또는 재렌더 때문에 큰 레이아웃 이동이 발생하지 않는다.
- 홈은 데이터를 의도적으로 지연 로드하므로 `Loading…` 상태를 표시하지 않는다.

## 7. 디자인 상세 기준

기존 시각 브리프의 “탐험가의 현장 도구 + 깨끗한 데이터 대시보드”를 유지한다.

### 7.1 시각 우선순위

1. 검색
2. 빠른 시작 과업
3. 데이터 탐색
4. 신뢰 원칙
5. 장식과 광고

### 7.2 레이아웃 토큰

- 최대 콘텐츠 폭: 현재 1400px 유지
- 홈 섹션 세로 간격: 데스크톱 72~88px, 모바일 48~64px 목표
- 카드 간격: 16~20px
- 카드 패딩: 20~24px
- 검색 실행 영역: 최소 높이 56px
- 모든 실행 컨트롤: 최소 44×44 CSS px
- 장식은 `aria-hidden="true"`로 처리하고 읽기 순서에 포함하지 않는다.
- 라이트·다크 테마 모두 기존 의미 토큰을 사용하며 홈 전용 하드코딩 색을 최소화한다.

## 9. SEO 계획

### 9.1 검색 의도

홈의 검색 의도는 `Palworld의 지도·팰·교배·제작·거점·서버 도구를 한곳에서 찾는 사이트 개요`다.

현재 메타 설명은 팰과 교배에만 치우쳐 있으므로 전체 범위를 정확히 반영하도록 수정한다.

- title: `Palworld 지도·팰·교배·제작 도구 | Palworld Helper`

- title: `Palworld Map, Pals, Breeding & Crafting Tools | Palworld Helper`
- description: `Explore the Palworld map, Pals and skills, breeding, crafting and base tools, game databases, and server settings across 17 languages.`

실제 문구는 길이와 각 언어 자연스러움을 검토한 뒤 확정한다.

### 9.2 SEO 완료 조건

- 홈 locale 17개 각각 고유하고 현지화된 title·description·OG/Twitter 텍스트
- canonical은 `https://palworld-helper.woofy.blog/{locale}`
- 17개 alternates와 `x-default → /en-US`
- 의미 있는 초기 HTML: H1, 설명, 빠른 시작 6개, 데이터 탐색 링크
- `h1` 정확히 1개
- `WebSite` 구조화 데이터 유지
- 검색 결과 페이지가 없으므로 검증되지 않은 `SearchAction` 구조화 데이터는 추가하지 않음

- 공개 HTML·메타·구조화 데이터에 게임 빌드/데이터 버전/업데이트 버전 없음

## 10. 접근성 계획

- 공통 landmark 순서와 하나의 `main`을 유지한다.
- 홈 검색 실행 컨트롤에 명확한 프로그램 라벨과 `aria-haspopup="dialog"`를 제공한다.

## 11. 성능 계획

### 11.1 예산

- 모바일 LCP ≤ 2.5초 목표
- CLS ≤ 0.1
- INP ≤ 200ms
- 홈 진입 시 대형 게임 데이터 JSON 추가 요청 0건
- 검색 데이터는 검색 실행 후에만 로드
- 광고 공간은 사전 예약
- 새 홈 전용 이미지가 필요하면 기존 최적화 자산 또는 CSS 장식을 우선하고, 초기 LCP 이미지는 100KB 안팎을 목표로 별도 검토

### 11.2 성능 방어

- 홈 콘텐츠를 정적 HTML에 모두 포함한다.
- 카드 아이콘은 기존 inline SVG 아이콘을 재사용한다.
- 지도 이미지나 엔터티 이미지를 카드에 사용한다면 `loading="lazy"`, 고정 width/height, non-requesting fallback을 적용한다.
- 검색 데이터 idle prefetch는 기본적으로 하지 않는다. 실제 성능 측정에서 필요성이 확인될 때만 별도 검토한다.
- 정적/런타임 같은 마크업을 사용해 재렌더 CLS를 줄인다.

## 12. Analytics·AdSense 계획

### 12.1 측정

기본 측정은 기존 SPA `page_view`만으로도 홈에서 목적지로 이동한 흐름을 볼 수 있다. 추가 이벤트는 의사결정에 실제로 필요할 때만 하나의 안정된 분류로 제한한다.

허용 가능한 선택안:

```text
event: home_navigation
params:
  destination: map | pals | breeding | crafting | base | server | catalog_group
```

규칙:

- 검색어 원문, 팰/아이템 이름, 서버 입력, 좌표, 수량은 전송하지 않는다.
- 같은 클릭으로 이벤트를 중복 전송하지 않는다.
- 동의와 sender 초기화가 성공하기 전에는 dedupe 상태를 소비하지 않는다.
- 홈 재렌더는 `page_view`를 추가로 발생시키지 않는다.
- 데이터가 적으면 이벤트를 추가하지 않고 기존 page view와 경로 전환만 사용한다.

### 12.2 출시 후 평가

가능한 경우 배포 전 28일과 배포 후 28일을 비교한다.

- 홈에서 구현된 도구/데이터 경로로 이동한 비율
- 첫 이동까지 필요한 클릭 수
- 홈 검색 열기와 결과 선택 비율(검색 원문 제외)
- 도착 route family 분포
- 홈 LCP·CLS·INP
- 광고 viewability와 Core Web Vitals의 동시 변화

트래픽·순위·수익을 보장하지 않으며, 표본이 부족하면 판단을 보류한다.

## 15. 테스트 추가 상세

### 15.1 단위/계약 테스트

- 홈 매니페스트의 ID·경로 중복 없음

- 공개 홈 카피에 빌드 번호 패턴 없음

- H1 1개, H2 순서 정상
- 모든 빠른 시작과 데이터 탐색 앵커가 crawlable
- `WebSite` JSON-LD가 visible content와 일치

- 초기 정적 링크가 앱 초기화 후 사라지지 않음
- 홈 진입 시 데이터 JSON 자동 로드 없음

- 언어·테마 변경으로 광고 재요청 없음
- 뒤로/앞으로에서 검색 다이얼로그나 메뉴의 오래된 상태가 남지 않음

## 18. 최종 완료 기준

다음 조건을 모두 만족해야 홈 개편을 완료로 본다.

### 제품

- 사용자가 홈에서 한 번의 선택으로 지도, 팰, 교배, 제작, 거점, 서버 도구에 진입할 수 있다.
- 모든 구현 데이터베이스가 네 개 그룹 안에서 발견 가능하다.
- 미구현 기능·가이드·업데이트·내 목록을 노출하지 않는다.

### 콘텐츠와 정확성

- 홈의 모든 게임 관련 설명이 현재 제공 기능과 일치한다.
- “모든 데이터 검증 완료” 같은 과장된 전역 주장이 없다.
- 교배 독립 검증 보류 상태를 “검증 통계”로 오해하게 하는 숫자를 사용하지 않는다.
- 공개 버전·빌드·데이터 갱신 번호가 없다.

### 현지화

- 공식 17개 locale 모두 누락·fallback 없이 완성된다.
- 게임 용어는 공식 현지화 우선이며 번역 provenance가 기록된다.

### UI·접근성

- 360~1440px와 200% zoom에서 수평 오버플로가 없다.
- 라이트·다크·시스템 테마와 reduced motion이 동작한다.
- 키보드·포커스·스크린리더·44px 터치 대상 게이트를 통과한다.

### SEO·성능

- 초기 HTML과 런타임 홈의 콘텐츠·링크·메타가 일치한다.
- locale별 title·description·canonical·hreflang·OG·H1이 정확하다.
- 홈 진입 시 대형 게임 데이터 파일을 불러오지 않는다.
- LCP, CLS, INP 목표를 유지하고 광고로 인한 레이아웃 이동이 없다.
- 사이트맵 URL 수, 물리 HTML 수, 배포 파일 예산이 기존 아키텍처와 일치한다.

### 측정·배포

- 검색 원문과 사용자 입력이 Analytics에 전송되지 않는다.
- 같은 홈 pathname의 재렌더가 page view를 중복 전송하지 않는다.
- 자동 검사와 브라우저 검사가 통과한다.
- 프로덕션 배포는 사용자가 별도로 승인한 경우에만 수행한다.
